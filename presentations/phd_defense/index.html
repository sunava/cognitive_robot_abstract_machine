Robots that help in everyday life must master everyday actions

  • Household environments are open-ended: objects, tools, and goals vary from one execution to the next.
  • Instructions written for humans — recipes, wikiHow — leave almost everything unsaid.
  • A robot cannot ask "how, exactly?" — it needs the missing knowledge before it moves.

The gap between instruction and motion

Natural-language instructions underdetermine robot action.

Even within a single action category such as cutting, execution depends on object properties (a peel, a core), the task variation (halving vs. slicing), the available tools, and the situational context.

The knowledge that fills this gap exists — in how-to guides, encyclopedias, and human common sense — but not in a form a robot can execute.

Research questions

  • RQ1 — How can action knowledge from web sources be represented so that robots can use it to parameterise manipulation actions?
  • RQ2 — How can a single generalized action plan cover task variations of an action category (e.g. halving, slicing, dicing for cutting)?
  • RQ3 — How can such plans transfer across objects, tools, robots, and environments without re-programming?

Foundations: the Cognitive Robot Abstract Machine

  • In CRAM, robot behaviour is written as generalized plans — programs with decision points left open.
  • Open decisions are expressed as designators: symbolic descriptions of actions, objects, and locations.
  • At runtime, designators are resolved against knowledge and perception — the same plan yields different motions in different situations.

This talk runs on the same idea — every slide is a designator being resolved and performed.

Approach: from written instructions to robot motion

instruction

Natural-language task from a recipe or how-to guide — "slice the cucumber".

actionable knowledge graph

Web-acquired knowledge, structured per action category: objects, tools, task variations, motion parameters.

generalized action plan

One CRAM plan per action category; designators query the AKG to fill open parameters.

execution

Parameterised motions on simulated and real robots — different objects, tools, variations.

Knowledge acquisition and plan structure are decoupled: new task variations extend the graph, not the code.

Actionable Knowledge Graphs make web knowledge executable

  • Built from web sources — how-to guides, recipes, lexical resources — and curated ontologies.
  • Per action category, the graph links task variations, object properties, and tools to body-motion parameters.
  • Actionable: every path through the graph terminates in parameters a plan can execute — not just facts about the action.
